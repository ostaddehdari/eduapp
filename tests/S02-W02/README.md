# آزمون پذیرش Gateway و OpenAPI

این مجموعه یک Gateway واقعی HTTP را روی پورت موقت loopback اجرا می‌کند. احراز هویت، دادهٔ مدارس و ثبت نتیجهٔ درخواست با آداپتورهای آزمایشی در حافظه انجام می‌شود.

```bash
node --import tsx --test tests/S02-W02/gateway-acceptance.test.mjs
node scripts/gateway-contract.mjs check
```

| سناریو | نتیجهٔ مورد انتظار |
| --- | --- |
| یک actor در دو مدرسه، هرکدام با فهرست خودش | صفحهٔ اول و دوم فقط دادهٔ همان مدرسه را برمی‌گردانند |
| cursor متعلق به مدرسهٔ دیگر | خطای عمومی `400 INVALID_REQUEST`، بدون بدنهٔ داده |
| کلید تکرارپذیری یکسان در دو مدرسه | هر مدرسه یک ثبت جدا دارد، بازپخش نتیجهٔ خودش را می‌دهد و اختلاف payload داخل همان مدرسه `409` می‌شود |
| پرشدن بودجهٔ یک مدرسه | مدرسهٔ اول `429` همراه `Retry-After` می‌گیرد و بودجهٔ مدرسهٔ دوم برقرار است |
| فراخوانی SDK روی HTTP | سلامت و نسخه خوانده می‌شوند و خطای آمادگی `503` با شناسهٔ درخواست به SDK می‌رسد |

چک اجباری `ci / repository-policy` این مجموعه، تست‌های Gateway، بازتولید SDK و بررسی سازگاری OpenAPI را اجرا می‌کند. برای بررسی diff در checkout محلی، SHA کامل commit مبنا را به انتهای فرمان `check` اضافه کنید. برای گزارش وضعیت، آزمون‌های آداپتور مصنوعی را از آزمون IAM و ذخیره‌ساز واقعی دامنه متمایز کنید.
