- شناسه: `S01-W02`
- نسخه: `1.0.0`
- وضعیت: پذیرفته‌شده
- اولویت: `P0`
- الزامات: `FR-003` و `FR-006`
- قرارداد مبنا: [`../contracts/S01-W02.md`](../contracts/S01-W02.md) نسخه `1.0.0`
- نسخه ماشین‌خوان: [`S01-W02.json`](S01-W02.json)

## ۱. مسئله و نتیجه محصول

خریدار باید از انتخاب پلن تا پرداخت تأییدشده و ایجاد نخستین مدرسه، یک مسیر روشن و قابل ادامه داشته باشد. نتیجه موفق فقط نمایش پیام پرداخت نیست: یک اشتراک فعال، دقیقاً یک Tenant، عضویت مالک و یک مدرسه مستقل یا شعبه‌ای هم‌Tenant باید ساخته شوند. تکرار درخواست، callback جعلی یا شناسه Tenant دیگر نباید اثر اضافه یا افشای داده ایجاد کند.

این PRD قرارداد عملیاتی و سناریوهای پذیرش را تعریف می‌کند؛ پیاده‌سازی Backend، migration، اتصال درگاه واقعی و تغییر production در محدوده این Task نیست.

## ۲. کاربران و مسئولیت‌ها

| Actor | هدف | مرز قطعی |
|---|---|---|
| Visitor | مقایسه نسخه فعال پلن‌ها | فقط `listPlans` و بدون عملیات نوشتن |
| Authenticated Buyer | ایجاد checkout و تلاش پرداخت | فقط invoice متعلق به payer |
| Payment Provider | اعلام وضعیت پرداخت | فقط callback امضاشده یا قابل‌استعلام |
| Provisioning Service | ساخت Tenant از اشتراک فعال | تکرارپذیر بر پایه `subscription_id` |
| Tenant Owner | ساخت سازمان و نخستین مدرسه | فقط در Tenant فعال خودش |
| Platform Admin | بازیابی استثنایی | با مجوز ویژه و audit اجباری |

## ۳. مسیر عملیاتی

| گام | عملیات | خروجی قابل مشاهده | وضعیت |
|---:|---|---|---|
| ۱ | `listPlans` | نسخه‌های فعال و قیمت ثابت نمایش داده می‌شوند | `PLAN_SELECTED` |
| ۲ | `createCheckout` | checkout و invoice با نسخه پلن ثابت ساخته می‌شود | `CHECKOUT_CREATED` |
| ۳ | `createPaymentAttempt` | مسیر امن درگاه یا دستور پرداخت برمی‌گردد | `PAYMENT_PENDING` |
| ۴ | `receivePaymentWebhook` | پرداخت در سرور تأیید و رویداد تکراری حذف می‌شود | `PAYMENT_VERIFIED` |
| ۵ | `createTenant` | یک Tenant و context مالک ساخته می‌شود | `TENANT_ACTIVE` |
| ۶ | `createOrgUnit` | ریشه مدرسه یا ساختار مجموعه/شعبه ساخته می‌شود | `FIRST_ORG_CREATED` |
| ۷ | `createSchool` | مدرسه به org unit هم‌Tenant متصل می‌شود | `FIRST_SCHOOL_CREATED` |
| ۸ | `getMyCapabilities` | مجوز و entitlement مؤثر نمایش و onboarding کامل می‌شود | `ONBOARDING_COMPLETE` |

اگر مرورگر پس از پرداخت بسته شود، وضعیت از داده سمت سرور ادامه می‌یابد؛ callback کلاینت منبع حقیقت نیست. استفاده دوباره از یک idempotency key با بدنه متفاوت با `409` رد می‌شود.

## ۴. قواعد کسب‌وکار

1. فقط نسخه فعال و immutable پلن قابل خرید است.
2. callback به‌تنهایی اشتراک را فعال نمی‌کند؛ امضا یا استعلام سرور Provider الزامی است.
3. پنج بار تحویل یک `provider_event_id` فقط یک provider event، اثر ledger، entitlement، activation و Tenant می‌سازد.
4. Provisioning با `subscription_id` تکرارپذیر است.
5. parent سازمان و org unit مدرسه باید متعلق به همان Tenant باشند؛ شناسه خارجی با خطای غیرقابل افشا رد می‌شود.
6. درخت سازمان چرخه ندارد؛ کد root در Tenant و کد sibling زیر یک parent یکتا است.
7. permission و entitlement جداگانه ارزیابی می‌شوند؛ داشتن نقش بدون قابلیت پلن یا بالعکس کافی نیست.

## ۵. دو مدل سازمانی پذیرفته‌شده

### مدرسه مستقل

`Tenant → Root School Org Unit → School`

`parent_id` ریشه تهی است و `tenant_id` مدرسه با org unit برابر است. این مسیر نباید کاربر را مجبور به ایجاد شعبه صوری کند.

### مجموعه شعبه‌ای

`Tenant → Collection Org Unit → Branch Org Unit → School`

والد شعبه در همان Tenant است. اتصال مدرسه به شعبه و جابه‌جایی بعدی org unit به کنترل نسخه و چرخه نیاز دارد.

## ۶. مرز مالکیت داده

| مالک | تنها جداول قابل نوشتن در این مسیر | نوشتن مستقیم ممنوع |
|---|---|---|
| IAM | `identities`, `sessions` | Tenant و ledger |
| Billing | کاتالوگ پلن، اشتراک، invoice، تلاش/رویداد پرداخت، ledger و entitlement | `tenants`, `org_units`, `schools` |
| Tenancy | `tenants`, `org_units` | ledger، entitlement و school |
| Access | `memberships`, `roles`, `role_bindings` | invoice، org و school |
| School | `schools` | Tenant، org و ledger |
| Platform | outbox، inbox dedupe و audit | رکوردهای دامنه‌ای |

هماهنگی بین مالک‌ها فقط از API یا رویداد نسخه‌دار انجام می‌شود. هیچ سرویس مصرف‌کننده‌ای از `tenantId` پیام بیرونی برای مجوز اعتماد نمی‌کند.

## ۷. سناریوهای پذیرش

### `happy-independent-school`

با پلن فعال، خریدار احرازشده و پرداخت تأییدشده؛ پس از checkout و provisioning، مالک یک org unit ریشه و مدرسه می‌سازد. دقیقاً یک اشتراک و Tenant وجود دارد، مدرسه و org هم‌Tenant هستند و onboarding کامل می‌شود.

### `happy-branched-school`

مالک Tenant پرداخت‌شده مجموعه، شعبه هم‌Tenant و مدرسه متصل به شعبه می‌سازد. درخت بدون چرخه است و قابلیت مدرسه فقط در scope مجاز بازمی‌گردد.

### `duplicate-payment-event`

یک رویداد معتبر پنج بار تحویل می‌شود. فقط یک provider event، اثر ledger، entitlement، activation و Tenant ایجاد می‌شود و تکرارها پاسخ idempotent می‌گیرند.

### `unverified-payment-callback`

امضا و استعلام نامعتبر است. `PAYMENT_NOT_VERIFIED` بازمی‌گردد و ledger، entitlement، activation و Tenant ساخته نمی‌شوند.

### `cross-tenant-parent`

مالک Tenant A شناسه parent از Tenant B می‌فرستد. `ORG_PARENT_NOT_FOUND` بازمی‌گردد و وجود Tenant B افشا نمی‌شود.

### `org-cycle`

جابه‌جایی پیشنهادی یک node را جد خودش می‌کند. `ORG_CYCLE` بازمی‌گردد و نسخه درخت تغییر نمی‌کند.

### `duplicate-sibling-code`

کد normalize‌شده تکراری زیر یک parent ارسال می‌شود. `ORG_CODE_CONFLICT` بازمی‌گردد و ردیف اضافه نوشته نمی‌شود.

### `school-org-other-tenant`

مالک Tenant A مدرسه را به org unit از Tenant B متصل می‌کند. `ORG_UNIT_NOT_FOUND` بازمی‌گردد و داده Tenant B افشا یا تغییر نمی‌کند.

## ۸. مشاهده‌پذیری و حریم داده

رویداد تکمیل گام، مدت مسیر و شمار retry با `step/result/error_code` ثبت می‌شوند. شماره کارت، payload خام Provider، نام/تلفن/ایمیل خریدار، داده کودک، slug مشتری و secret در metric یا log قرار نمی‌گیرند. API فقط `requestId` و کد خطای پایدار را در پاسخ افشا می‌کند.

## ۹. Definition of Done

- هر دو مدل مستقل و شعبه‌ای سناریوی پذیرش قابل اجرا دارند.
- تمام operationIdها در قرارداد پذیرفته‌شده و OpenAPI فعلی وجود دارند.
- همه سناریوهای قرارداد بدون ضعیف‌کردن نتیجه یا کد خطا در PRD حاضرند.
- replay پنج‌باره فقط یک اثر مالی و provisioning دارد.
- تمام ۱۹ جدول قرارداد دقیقاً یک writer دامنه‌ای دارند.
- سند و telemetry به کارت، داده کودک یا secret نیاز ندارند.

## ۱۰. خارج از محدوده

پیاده‌سازی Backend و migration، اتصال درگاه واقعی، سال/کلاس/دانش‌آموز/حضور، و هر تغییر Nginx یا داده production در این Task انجام نمی‌شود.
