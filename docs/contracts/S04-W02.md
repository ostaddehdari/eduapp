# S04-W02 · Organization tree

| Contract | Version | Requirement |
| --- | --- | --- |
| S04-W02 | 1.0.0 | FR-003 · CORE-06 |

The Tenancy owner provides an active tenant with a parent-linked organization tree. A unit models a holding, company, collection, branch, school or institute. A school unit is the organizational attachment point for the future School owner's record. This component writes only Tenancy data and its approved outbox event. The commercial journey for an independent school and a branch school comes from [S01-W02](S01-W02.md).

## Allowed parent relationships

| Unit kind | May be a root | Allowed parent kinds |
| --- | --- | --- |
| `holding` | Yes | None |
| `company` | Yes | `holding` |
| `collection` | Yes | `holding`, `company`, `collection` |
| `branch` | No | `company`, `collection` |
| `school` | Yes | `collection`, `branch` |
| `institute` | Yes | `branch` |

Each unit has an ID, parent ID or null, kind, code, display name and version. A root code is unique within its tenant. A child code is unique among its siblings. Foreign parent IDs and absent parent IDs return the same `ORG_PARENT_NOT_FOUND` without exposing another tenant's data. Changes preserve descendants because a move updates only the unit's parent and version. The operation rejects a parent chain that encounters the unit or lacks a root. Nesting one collection in another is allowed within the same tenant.

## HTTP operations

| Operation ID | Behavior |
| --- | --- |
| `listOrgUnits` | List the authorized active tenant's units in ascending ID order with an opaque cursor. |
| `getOrgTree` | Page through the same parent-linked records. Consumers assemble the checked tree using `parentId` across pages. |
| `createOrgUnit` | Create an allowed unit and return 201 with its initial version. |
| `moveOrgUnit` | Relocate a unit with `If-Match` set to its strong integer ETag. Return 200 and the unit's current ETag. |

Create accepts `kind`, `code`, `name`, optional nullable `parentId`, and `idempotencyKey`. The code uses 1–64 lowercase ASCII letters, digits and single hyphens between groups. The normalized display name accepts 1–120 Unicode code points after trimming. The required body key accepts 8–128 ASCII letters, digits, periods, underscores, tildes or hyphens. It is scoped to the tenant and acting identity. A successful retry returns the original creation snapshot, even after the unit moves. A changed request with the same key returns `IDEMPOTENCY_CONFLICT`.

Move accepts `parentId` as a UUID or explicit null. A missing precondition is 428, a stale version is 412, and an invalid hierarchy is 422. `ORG_CYCLE` and `ORG_CODE_CONFLICT` both return 409. A move to the current parent returns the unchanged version and appends no event. Resource paths and lookup keys never select a tenant.

## Authorization, storage and effects

| Principal | Authorized use |
| --- | --- |
| Active tenant-wide member | By explicit Access authorization, `tenancy.org.read` permits listing or retrieving the tree and `tenancy.org.write` permits creation and moves. |
| School-bound member | School operations continue to use their own scoped owner policy. Tenant-wide tree ops are denied. |
| Tenant runtime database role | Reads and mutates its own tenant-bound organizational data. The approved producer function appends `tenancy.org_unit_changed.v1`. |
| Other domain owner or public client | No direct read or write access to the tree tables. |

Migration `0008-organization-tree.sql` extends `tenancy_organization.org_units` with name and version and creates `tenancy_organization.org_unit_create_requests`. Older units without a name display their existing code and start at version 1. Both tables use tenant row-level isolation and same-tenant references. The receipt stores digests of the request key and normalized fields with the original response. Receipts persist with their unit.

Before a write, the transaction verifies and locks the active tenant row, then acquires a tenant-scoped advisory lock. Competing writers resolve the current parent graph and version while holding that lock. Database uniqueness and the optimistic update predicate independently enforce siblings and versions. A suspended or deleted tenant cannot list or mutate the tree.

A successful creation or real move appends the existing versioned `tenancy.org_unit_changed.v1` event with `org_unit_id` and `version`. The outbox record, update and any creation receipt commit together. The event deliberately omits display names, query inputs, request keys and credentials. Existing consumers and the `org_unit_id+version` logical identity come from [S01-W03](S01-W03.json).

See the [acceptance tests](../../tests/S04-W02/README.md). Do not remove the additive schema from an environment with live receipts as a code rollback.
