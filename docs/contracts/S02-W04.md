# S02-W04 · Transactional event delivery

| Field | Value |
| --- | --- |
| Version | 1.0.0 |
| Scope | S02-W04-T01, S02-W04-T02, S02-W04-T03 |
| Requirement | DATA-001 |
| Owners | Publishing domain, Platform delivery, receiving domain |

The event names, producers, receivers and semantic revision keys in [S01-W03](S01-W03.json) are unchanged. The [PostgreSQL isolation contract](S02-W03.md) defines the tenant scope, outbox, inbox and permissions. This contract adds the transport envelope and failure behavior. It introduces no HTTP operations. RabbitMQ is an optional proof of concept. PostgreSQL is the source of truth for pending events.

## Producer and transport contract

| Field | Rule |
| --- | --- |
| `id` | Stable UUID for the event. Use the same ID when retrying publication. A new semantic revision receives its own ID. |
| `tenantId` | UUID derived by the producer from the authorized transaction. The worker checks its assigned tenant set before processing. |
| `type` | Existing versioned event name from the registry. |
| `occurredAt` | UTC date-time at which the outbox record occurred. |
| `payload` | Object containing the minimal owner-approved data for the event. No secrets, credentials or unnecessary personal data. |

The domain owner calls `platform_audit_jobs.append_outbox` in the same transaction as its owned data change. The append function validates the producing database role and binds the tenant. A rollback removes both changes. The Platform worker locks one pending row within a scoped transaction using `FOR UPDATE SKIP LOCKED`. It marks the row published after it receives confirmation for every registered consumer queue. Persistent messages use durable queues. The worker checks mandatory returns as well as broker confirms and leaves the outbox row pending on any failure. Duplicate deliveries can follow a lost confirm, a partial fan-out, or a database commit failure after confirmation.

## Consumer and retry contract

The consumer verifies the envelope, expected route and tenant assignment. The transport credentials and registered route establish delivery provenance. Domain authorization and the actor's access to any resource remain decisions of the receiving owner. IAM events with no tenant-bound effect stay outside this tenant worker.

The Platform inbox inserts the `(tenant_id, consumer, event_id)` marker before the owned durable handler and commits both together in the same PostgreSQL transaction. The globally unique `(consumer, event_id)` key rejects replay under a conflicting tenant. Exact duplicates skip the handler and can be acknowledged. Consumers call their owned application services. They do not acquire another owner's table grants. When the effect targets an external provider, the owner stages its own outbox entry or supplies a stable provider idempotency key.

RabbitMQ acknowledges after the commit. A lost acknowledgement can cause another delivery of the same event. Transient handler errors roll back the inbox and effect. The worker retries confirmed publication to the same durable consumer queue after a bounded delay and acknowledges the previous delivery only after that transfer. The default budget is three attempts. Invalid envelopes, invalid routes, unauthorized tenant assignments, tenant conflicts and exhausted attempts go to a dedicated DLQ for the receiver. A dead letter carries the event identifiers and fixed reason code, with no body or database error. A failed retry or DLQ transfer leaves the original delivery eligible for redelivery. An operator investigating a dead letter reads the original event through a separate authorized interface using the ID.

## Worker entry point

From `apps/worker`, run `pnpm start:delivery` in a disposable dev environment with `EDUAPP_PLATFORM_PG_URL` for the Platform worker, `EDUAPP_AMQP_URL` for the POC broker and `EDUAPP_EVENT_TENANTS` listing explicitly assigned tenant UUIDs. Supply credentials through the environment. The entry point handles the existing Platform audit routes. Queues for other receiving contexts retain messages until their owning services register handlers. Errors emit fixed process messages. The default `pnpm start` still starts the existing Nest worker.

- `node --test tests/S02-W04/*.test.mjs` verifies route compatibility, retry, replay and sanitized dead letters.
- Set `EDUAPP_TEST_AMQP_URL` for the real broker interruption, reconnection, redelivery and DLQ check.
- Set both `EDUAPP_TEST_AMQP_URL` and `EDUAPP_W04_PG_ADMIN_URL` for the combined PostgreSQL and RabbitMQ check. Use loopback fixture services and omit URL query options and fragments. The PostgreSQL administrator fixture uses a disposable database named `eduapp_w04_test`. The test exercises Billing producer and Platform worker roles, rollback, pending outbox recovery, same-transaction inbox and synthetic financial effect, and deduplication after broker redelivery.
