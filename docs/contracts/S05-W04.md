# S05-W04 · Checkout و صورتحساب

نسخه قرارداد: `1.0.0`؛ الزام `FR-006`؛ مالک داده و عملیات: Billing. مسیر داخلی تا تکمیل پرداخت verified؛ endpoint عمومی فعلاً عرضه نشده است.

| عملیات/رویداد | ورودی/خروجی | ضمانت |
| --- | --- | --- |
| `order(identity, planVersionId, modules, seats, requestKey)` | سفارش، subscription و invoice در وضعیت `pending_payment` | scope برابر tenant، مجوز مستقل، نسخه منتشرشده، ظرفیت و کلید تکرار UUID؛ محاسبه قیمت در تراکنش مالک |
| `transition(identity, orderId, grace, graceUntil)` | سفارش در grace با موعد معتبر | فقط سیاست مستقل Billing؛ بدون اعطای entitlement |
| `transition(identity, orderId, cancel)` | سفارش و invoice لغوشده | نگهداری داده مشتری و audit؛ تکرار لغو بی‌اثر |
| `billing.checkout.created.v1` | شناسه tenant، سفارش و invoice | رویداد خارجی در این ورک منتشر نمی‌شود؛ به outbox آتی وابسته است |

| جدول | مالک | سطح دسترسی runtime |
| --- | --- | --- |
| `commercial_billing.checkout_orders` | `eduapp_commercial_billing_owner` | SELECT، INSERT فیلدهای مجاز، UPDATE فقط status و grace_until؛ RLS اجباری |
| `commercial_billing.subscriptions`, `invoices` | Billing | داده همان tenant؛ pending/grace/cancelled و بدون حذف |
| `commercial_billing.plan_versions` | Billing | خواندن نسخهٔ منتشرشده؛ قیمت نسخه تغییر نمی‌کند |

| کنش | بازدیدکننده | عضو tenant مجاز | عامل چرخه مالی مجاز |
| --- | --- | --- | --- |
| ثبت سفارش | خیر | با `billing.checkout.create` و scope برابر tenant | فقط با سیاست جداگانه |
| تغییر grace/لغو | خیر | خیر | فقط `billing.checkout.grace` / `billing.checkout.cancel` |
| فعال کردن اشتراک / دریافت پول | خیر | خیر | در ورک پرداخت verified بعدی، خارج از این قرارداد |

خطاها: `INVALID_REQUEST` برای ورودی نامعتبر، `FORBIDDEN` برای scope یا مجوز، `NOT_FOUND` برای نسخه یا سفارش ناموجود، `VALIDATION_FAILED` برای ظرفیت و ماژول، `CONFLICT` برای درخواست تکراری با محتوای متفاوت یا گذار ناسازگار. کلید تکرار در هر tenant با قفل تراکنشی محافظت می‌شود. retry یک سفارش موجود را برمی‌گرداند و invoice تازه نمی‌سازد. قیمت در snapshot سفارش و invoice نگهداری می‌شود؛ تخفیف و قیمت جزئی ماژول/صندلی تا قرارداد صریح بعدی پذیرفته نمی‌شود. هیچ کدام از وضعیت‌های `pending_payment`، `grace` یا `cancelled` entitlement فعال ایجاد نمی‌کنند. migration `0015-checkout.sql` افزایشی است؛ برای production قبل از اجرا پیش‌پرواز پایگاه داده، پشتیبان و rollback جبرانی لازم است.
