# S03-W05 · Security audit

| Contract | Version | Requirement |
| --- | --- | --- |
| S03-W05 | 1.0.0 | CORE-08, SEC-001 |

An authorized owner appends credential-free audit facts for login, role changes, membership and invitation delegation, and sensitive data access. The Gateway supplies its server-generated request ID for correlation. Audit consumes the actor and current membership context resolved by the owner. It never treats a request header, URL parameter or event payload as proof of authorization.

## Internal event contract

| Event | Producer | Context and resource |
| --- | --- | --- |
| `security.login.v1` | IAM | Login outcome, verified actor when known, server request ID, and optional actual session and selected membership on success. The confidential IAM store holds this event. |
| `security.role_created.v1` | Access | Active tenant, acting membership, actor, request ID and created role ID. |
| `security.role_updated.v1` | Access | Active tenant, acting membership, actor, request ID and updated role ID. |
| `security.role_assigned.v1` | Access | Active tenant, acting membership, actor, request ID and binding ID. |
| `security.membership_delegated.v1` | Access | Active tenant, acting membership, actor, request ID and resulting membership ID. |
| `security.invitation_delegated.v1` | Access | Active tenant, acting membership, actor, request ID and invitation ID. |
| `security.sensitive_access.v1` | People or Access | Active tenant, acting membership, actor and request ID. An authorized object read can carry its resource ID; a collection read carries a constant scope marker. |

Tenant facts accept `success` or `denied`. A denial carries no requested resource ID. A recorded denial requires independently verified membership. An unidentified login attempt records only its outcome and generated request ID; a login error cannot acquire a claimed tenant or session context. Each store generates its own event ID and timestamp. The existing Gateway status codes and response envelopes still apply. These internal audit facts add no client-facing API or broker topic.

Only fixed action names, enumerated outcomes, generated identifiers and timestamps reach storage. Audit does not collect passwords, OTPs, invitation tokens, access tokens, headers, addresses, names, role rules, payloads, exception messages or stack traces. Treat internal actor, membership and session UUIDs as restricted data. Access to raw audit facts and retention are governed by environment-specific operator policy.

## Ownership and access

| Surface | Permission |
| --- | --- |
| IAM runtime | Append only to `identity_access.security_login_facts`. Cannot query or mutate saved facts. |
| Access and People runtime | Execute the Platform append function for event types assigned to their owner role. Cannot use the function without a bound tenant and valid membership. |
| Platform worker | Scoped read of its existing `platform_audit_jobs.audit_events` table. Existing owner-projected domain events retain their legacy write path. The worker cannot directly append security events, update or delete audit facts. |
| Gateway and public clients | No direct access to audit tables. |
| Support | An independently authorized, masked projection is the read boundary. This stage provides no public audit reader. |

Migration `0006-security-audit.sql` adds the private IAM login table and extends the existing Platform audit table. The Platform append function takes no tenant argument. It obtains tenant scope from the same transaction as the owner, validates the producer from its database login and rechecks and locks the active membership. The table remains protected by tenant RLS. IAM's optional server-resolved login context remains private in IAM; it does not create a Platform event or fan out to tenants. Existing IAM MFA facts remain independent of login facts.

## Failure behavior

Write owners append a success fact within the transaction that commits their security change. A storage failure aborts the transaction. Audit required for a sensitive read commits before the owner releases the response. Errors map to the Gateway's generic failure envelope. When an owner cannot verify membership, record no tenant fact. Security facts never authorize a command or change a session or role in response to playback.
