# S04-W05 · Versioned custom fields

| Field | Value |
| --- | --- |
| Version | 1.0.0 |
| Requirement | FR-005 / CORE-07 |
| Owner | Fields in the People and Fields context |

## API

| Operation | Request | Result |
| --- | --- | --- |
| `listFieldDefinitions` | `GET /v1/field-definitions`, optional `entityType` and `key` with standard pagination | `200` containing retained typed definition revisions |
| `createFieldDefinition` | `POST /v1/field-definitions`. JSON `entityType`, `key`, `label`, `type` and optional `constraints`, `required`, `expectedVersion` | `201` with the newly published schema revision and its version ETag |
| `listFieldValues` | `GET /v1/field-values/{entityType}/{entityId}`, with `schoolId` for a student and standard pagination | `200` containing retained value revisions for that exact resource |
| `createFieldValue` | `POST /v1/field-values/{entityType}/{entityId}`, with `schoolId` for a student. JSON `definitionId`, `value` and `expectedVersion`. | `201` with the appended value revision and its version ETag |

Entity types are `school` and `student`. A school resource derives its school ID from the path. For a student, `entityId` is the enrolled person's ID and `schoolId` is required. A matching active enrollment and actual school organization scope are required. IDs outside the authorized scope return a generic `404`.

Definitions are grouped by Tenant, entity type and key. Start with expected version zero. A change creates a new immutable revision using the prior version as the expected one. Values append to the exact Tenant, school, entity and definition revision. A value's first revision also starts at expected version zero. Stale or conflicting revisions return `409`. New values use the latest definition. Previous definitions and previously written values remain readable with current authority. For an optional definition, a JSON null appends an explicit clear and preserves earlier values.

## Validation and access

Keys use lowercase ASCII letters, numbers and single underscores, 2–48 characters, starting with a letter. Labels are plain text up to 100 characters. Core identifiers and sensitive key families such as identity documents, credentials, private contact details, protected attributes, health and financial data are reserved. Entry data must stay within the school's purpose and the configured fields policy.

| Type | Declarative constraint |
| --- | --- |
| `text` | Plain text of at most 500 characters, default 160 |
| `integer` | Inclusive minimum and maximum within ±1 billion |
| `boolean` | JSON true or false |
| `date` | Calendar date between 1900 and 2200, optionally narrowed by date bounds |
| `choice` | 1–32 distinct plain-text options of up to 80 characters |

The schema accepts only the listed attributes and constraints. It rejects executable markup, JavaScript and unknown constraint attributes. The application never interprets field names, labels or values as code.

| Principal | Allowed boundary |
| --- | --- |
| Verified Tenant and organization member | Read definitions only with explicit definition-read permission in the selected scope. |
| Tenant-level field administrator | Publish definitions with explicit definition-write authority. |
| School field operator | Read or write the exact verified school with the corresponding school permission. |
| Explicitly authorized student field operator | Read or write values for a specific active student's school scope. School authority alone grants no student access. |
| Fields owner runtime | Store definitions and values under forced Tenant RLS. Writes append records and report only generic scope errors. |
| School and Tenancy | Resolve and lock active resource and scope through owned predicates that return no student profile. |

Value revisions store actor, request ID and timestamp for audit without including any value in application events. The definition transaction appends the existing `fields.definition_published.v1` notification with only the new definition ID and schema version. Runtime credentials have no direct School, Tenancy or People table privileges.

`0011-custom-fields.sql` augments foundation storage and leaves untyped legacy rows intact. An unscopeable legacy value is not published through the school-scoped API. A reviewed migration can classify those rows when their actual owner and scope are known. Run the acceptance suite against disposable PostgreSQL 17. Restore an already migrated environment through a reviewed forward migration or tested backup.
