# قرارداد حکمرانی داده کودک و ارائه‌دهندگان

- شناسه: `S01-W04`
- نسخه: `1.0.0`
- وضعیت: قرارداد حکمرانی پذیرفته‌شده؛ تصمیم‌های بیرونی هنوز باز
- الزام: `SEC-002`
- قرارداد ماشین‌خوان: [`S01-W04.json`](S01-W04.json)

## ۱. مرز این تصمیم

این سند جایگزین نظر حقوقی یا قرارداد تجاری نیست. کشور محل پردازش، مبنای قانونی، حداقل سن، انتقال برون‌مرزی، نام Provider، مبلغ بودجه و SLA هنوز از اسناد پروژه اثبات نشده‌اند. بنابراین همه قابلیت‌های حساس تا ثبت شواهد و تصویب چندنقشی، `default deny` هستند.

هفت تصمیم باز به رکورد نسخه‌دار تبدیل شده‌اند: محل داده کودک، سیاست رضایت سرپرست، درگاه پرداخت، پیامک، object storage، دستگاه حضور و اتصال مالی مدرسه. هر رکورد مالک تصمیم، تصویب‌کنندگان، مهلت برنامه‌ریزی، مدارک لازم و خطای پایدار دارد.

## ۲. مهلت و مسئول تصمیم

تصمیم‌های داده کودک و رضایت تا `2026-12-08` برای بررسی حقوقی/امنیتی برنامه‌ریزی شده‌اند. پنج قرارداد Provider تا `2026-12-15` باید قرارداد امضاشده، POC، محل پردازش و بودجه مصوب داشته باشند. این تاریخ‌ها موعد برنامه پروژه‌اند و حکم قانونی یا تعهد Provider نیستند.

تا تکمیل evidence، `activation_permitted=false` باقی می‌ماند. هیچ نقش منفردی نمی‌تواند قرارداد، بودجه، امنیت و مبنای قانونی را هم‌زمان خودتصویب کند.

## ۳. داده کودک و رضایت

- داده کودک «بسیار حساس»، tenant-scoped و حداقلی است.
- رابطه سرپرست باید پیش از ثبت رضایت تأیید شود.
- رضایت برای purpose/scope مشخص، نسخه‌دار، قابل انقضا و قابل لغو است.
- لغو رضایت پردازش جدید را متوقف می‌کند؛ استثنای نگهداری مالی/audit باید مستند باشد.
- فایل مدرک یا secret در `evidence_ref` قرار نمی‌گیرد.
- raw biometric template یا تصویر بیومتریک در SaaS ذخیره نمی‌شود.
- محل پردازش، retention، export و حذف باید پیش از production تصویب و audit شوند.

## ۴. قرارداد Provider

| نوع | حالت مجاز آغازین | دروازه‌های اصلی |
|---|---|---|
| درگاه پرداخت | verify سمت سرور و write کنترل‌شده | قرارداد، sandbox، idempotency، reconciliation، بودجه |
| پیامک | خروجی حداقلی و template-based | قرارداد پردازش، rate/quiet hours، TTL، بودجه |
| فایل | object خصوصی و encrypted | محل پردازش، ACL، signed read، حذف، بودجه |
| دستگاه حضور | event امضاشده و dedupe | بدون biometric خام، POC، تأیید انسانی، بودجه |
| مالی مدرسه | snapshot فقط‌خواندنی | API مستند، credential محدود، stale state، reconciliation، بودجه |

Credential فقط به‌صورت reference به secret manager ثبت می‌شود؛ secret، token، password و کلید در DB حکمرانی، Git یا log مجاز نیست.

## ۵. مالکیت داده

هشت جدول قراردادی مالک یکتا دارند. metadata تصمیم و Provider در `platform_audit_jobs`، نسخه policy رضایت در `people_fields` و رضایت واقعی سرپرست در `school_enrollment` نگهداری می‌شود. انتقال مالکیت نیازمند major version، ADR و migration/reconciliation است.

## ۶. API و رویداد

۹ operation نسخه `v1` و ۶ event نسخه‌دار تعریف شده‌اند. همه operationها در وضعیت `contract_only_not_implemented` هستند و این سند وجود endpoint زنده را ادعا نمی‌کند. فعال‌سازی endpoint در Stage اجرایی بعدی نیازمند OpenAPI، authorization، audit و تست منفی است.

## ۷. خطاهای fail-closed

تصمیم نامصوب، رضایت نامعتبر، قرارداد امضانشده، بودجه نامصوب، محل پردازش نامعلوم، secret inline، biometric خام و write مالی همگی رد می‌شوند. خطای عمومی فعال‌سازی `PROVIDER_ACTIVATION_GATES_INCOMPLETE` است؛ API نباید نام secret یا جزئیات قرارداد خصوصی را افشا کند.

## ۸. بازگشت

این Task فقط قرارداد و validator ایجاد می‌کند و production، داده، Provider یا migration را تغییر نمی‌دهد. rollback با Git revert است. حذف داده واقعی یا لغو قرارداد Provider عملیات جدا و نیازمند runbook مصوب خواهد بود.
