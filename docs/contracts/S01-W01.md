## 1. هدف و قاعده تصمیم

این سند مرجع اجرایی تیم برای تشخیص «منبع معتبر»، اولویت محصول، مالکیت داده، قراردادهای API و رویداد و کنترل مجوز است. هیچ رفتار مشاهده‌شده در HAR به‌تنهایی قرارداد محصول جدید محسوب نمی‌شود. هر تغییر این سند باید نسخه، PR، دلیل تصمیم و اثر روی API/داده را ثبت کند.

ترتیب اعتبار منابع:

1. `proposal.json` و الزامات شناسه‌دار مخزن `ostaddehdari/eduapp` برای معیارهای قابل آزمون.
2. `proposal.md` نسخه 2.1 برای مرز P0/P1، امنیت و معماری آغاز.
3. `EduSaaS_Engineering_Blueprint_v2.0` برای معماری فنی، bounded contextها و الگوی استقرار.
4. پروپوزال جامع مدیریت مجموعه آموزشی برای پوشش محصول، پنل‌ها و قابلیت‌های P2/P3.
5. پروپوزال HAR v1.1 فقط برای شاهد وجود حوزه‌ها و عملیات سامانه مرجع؛ HAR منبع API جدید یا صحت رفتار انتهابه‌انتها نیست.

در تعارض منابع، P0/P1 نسخه 2.1 ملاک نسخه اول است. قابلیت‌های سند جامع حذف نمی‌شوند و در P2/P3 باقی می‌مانند تا با revision رسمی برنامه جابه‌جا شوند.

## 3. واحد استقرار و مالکیت دامنه

مرز منطقی سرویس با کانتینر مستقل یکسان نیست. فاز آغاز می‌تواند API ماژولار، Worker، Nuxt و React داشته باشد؛ جداسازی runtime فقط با سنجه بار، تیم، SLA یا امنیت انجام می‌شود. جدول زیر مالک انحصاری داده و قرارداد را مشخص می‌کند.

| Context | مالک داده | جداول/منابع اصلی | API یا رویداد مالک | مصرف‌کنندگان مجاز |
|---|---|---|---|---|
| IAM/Access | Identity | identities, sessions, memberships, roles, role_bindings | `/v1/auth/*`, `/v1/me/capabilities`, `identity.session-revoked.v1` | همه contextها از طریق policy contract |
| Tenant/Organization | Tenancy | tenants, legal_entities, org_units, org_unit_paths | `/v1/tenants`, `/v1/org-units`, `tenancy.org-unit-moved.v1` | IAM، School، Sites، Billing |
| Persons/Fields | People | persons, field_definitions, field_values | `/v1/users`, `/v1/field-definitions`, `people.profile-updated.v1` | School و فرم‌ها با field mask |
| Commercial/Billing | Billing | plans, subscriptions, invoices, payment_attempts, ledger_entries, entitlements | `/v1/subscriptions/*`, `/v1/webhooks/payments/*`, `billing.entitlement-activated.v1` | Gateway، Sites و ماژول‌های دارای entitlement |
| Sites/Domains/Pages | Sites | sites, domains, page_revisions | `/v1/sites/*`, `/v1/pages/*`, `sites.page-published.v1` | Nuxt renderer و Asset service |
| Assets | Assets | media_assets, upload_sessions, storage_policies | `/v1/assets/*`, `assets.asset-ready.v1` | Sites، School، LMS با policy |
| School/Enrollment | School | schools, academic_years, classes, enrollments, guardian_links | `/v1/schools/*`, `/v1/enrollments`, `school.enrollment-activated.v1` | Attendance، Notifications و پنل‌ها |
| Attendance | Attendance | device_events, attendance_records, attendance_revisions | `/v1/attendance/*`, `/v1/devices/*`, `attendance.record-confirmed.v1` | School و Notifications |
| Notifications | Communications | templates, message_jobs, message_attempts, receipts | `/v1/message-jobs`, `communications.message-delivered.v1` | پنل‌ها؛ Provider فقط از Adapter |
| Integrations | Integrations | provider_connections, webhook_inbox, sync_snapshots | API داخلی Adapter، `integrations.sync-completed.v1` | دامنه مالک درخواست |
| Audit/Jobs | Platform | audit_events, outbox_events, inbox_dedup, job_runs | API داخلی و event envelope مشترک | همه contextها با حداقل payload |

قواعد قطعی مالکیت:

- هیچ Context به جدول Context دیگر `JOIN` مستقیم یا write مستقیم ندارد.
- شناسه خارجی فقط reference است؛ صحت آن با API، projection یا event نسخه‌دار کنترل می‌شود.
- تمام داده Tenant-owned دارای `tenant_id NOT NULL`، قید مرکب مناسب و تست جداسازی دو Tenant است.
- PostgreSQL منبع حقیقت تراکنشی، Object Storage منبع باینری و Redis فقط داده قابل بازسازی است.
- داده کودک، سلامت، مشاوره و حقوق با طبقه‌بندی highly-sensitive و field mask مستقل نگهداری می‌شود.

## 4. قرارداد مشترک API نسخه 1

Base path عمومی محصول: `/eduapp/api/v1`. Gateway ممکن است در شبکه داخلی `/v1` را به سرویس‌ها route کند؛ کلاینت عمومی نباید URL داخلی را بداند.

Swagger UI یکپارچه در `https://srun.ir/eduapp/api/docs` و سند OpenAPI ماشین‌خوان در `https://srun.ir/eduapp/api/openapi.json` منتشر می‌شود. تمام APIهای HTTP محصول باید در کاتالوگ OpenAPI حاضر باشند؛ endpointهای داخلی یا حساس نیز مستند می‌شوند، اما اجرای آن‌ها همچنان به احراز هویت، scope و مجوز وابسته است و نمایش Swagger مجوز عملیاتی ایجاد نمی‌کند.

قواعد مشترک:

- JSON با UTF-8؛ زمان ذخیره و API به UTC/ISO 8601؛ تاریخ جلالی فقط presentation.
- پاسخ موفق `{ "data": ..., "meta": { "requestId": "...", "version": "v1" } }`.
- خطا `{ "error": { "code": "STABLE_CODE", "message": "...", "details": [] }, "meta": { "requestId": "..." } }`.
- `401` برای نبود احراز؛ `403/404` بدون افشای منبع؛ `409` تعارض؛ `422` ورودی معنایی؛ `429` محدودیت نرخ.
- `Idempotency-Key` برای پرداخت، ثبت حضور، ایجاد اشتراک و عملیات دارای اثر خارجی.
- `If-Match` برای ویرایش همزمان منابع نسخه‌دار.
- pagination بر پایه cursor، limit سقف‌دار و filter/sort allowlist.
- هر سرویس OpenAPI 3.1 مستقل؛ Gateway سند عمومی نسخه‌دار و CI با breaking-change check منتشر می‌کند.

### 4.1 عملیات پایه مصوب

| عملیات | مالک | احراز/مجوز | اثر idempotent و خطا |
|---|---|---|---|
| `POST /auth/otp/request` | IAM | عمومی، rate limit و پاسخ غیرقابل تشخیص | challenge تکراری امن؛ `429` سقف تلاش |
| `POST /auth/otp/verify` | IAM | challenge معتبر | نشست جدید؛ OTP منقضی `422` |
| `POST /auth/refresh` | IAM | refresh rotation | reuse کل خانواده نشست را revoke می‌کند |
| `GET /me/capabilities` | IAM | نشست + Tenant/Org context | permission و entitlement مستقل محاسبه می‌شوند |
| `POST /tenants` | Tenancy | platform tenant:create | slug یکتا؛ تکرار payload با key یک نتیجه |
| `POST /org-units` | Tenancy | org:manage در parent | parent خارج Tenant/چرخه `409` |
| `POST /subscriptions/checkout` | Billing | payer مجاز | invoice/attempt تکراری نمی‌شود |
| `POST /webhooks/payments/{provider}` | Billing | signature + timestamp + server verify | callback تکراری `200` بدون ledger دوم |
| `POST /assets/upload-sessions` | Assets | uploader + quota + scope | private by default؛ حجم/نوع نامعتبر `422/413` |
| `POST /pages/{id}/publish` | Sites | site:publish + entitlement | revision immutable؛ تعارض `409` |
| `POST /enrollments` | School | school:enrollment:create | سابقه سالانه حفظ؛ تعارض `409` |
| `POST /attendance/session-batches` | Attendance | teacher_of(class) | logical key تکراری اثر دوم ندارد |
| `POST /attendance/records/{id}/confirm` | Attendance | attendance:confirm در scope | revision و audit اجباری |

## 5. قرارداد رویداد

Envelope اجباری:

```json
{
  "eventId": "uuid",
  "eventType": "context.entity.past-tense-action.v1",
  "occurredAt": "2026-11-21T00:00:00Z",
  "producer": "service-name",
  "tenantId": "uuid-or-null",
  "correlationId": "uuid",
  "causationId": "uuid-or-null",
  "schemaVersion": 1,
  "data": {}
}
```

قواعد تحویل:

- تولید از transactional outbox همان تراکنش دامنه؛ مصرف با inbox dedup روی `(consumer,eventId)`.
- تضمین شبکه at-least-once است؛ مصرف‌کننده باید idempotent باشد.
- payload حداقلی و بدون شماره تماس، سند هویتی، کلید آزمون، token یا secret.
- retry با backoff محدود و DLQ؛ replay فقط با runbook و audit.
- تغییر ناسازگار با suffix نسخه جدید انجام می‌شود.

| Event | Producer | Consumer | داده حداقلی | اثر مجاز |
|---|---|---|---|---|
| `billing.payment-verified.v1` | Billing | Entitlements/Audit | paymentId, invoiceId, verifiedAt | فعال‌سازی دقیقاً یک entitlement |
| `billing.entitlement-activated.v1` | Billing | Gateway/Sites/School | tenantId, feature, limits, validTo | invalidation cache تصمیم دسترسی |
| `school.enrollment-activated.v1` | School | Attendance/Notifications | enrollmentId, schoolId, yearId | projection عضویت؛ بدون PII |
| `attendance.record-confirmed.v1` | Attendance | Notifications/Audit | recordId, enrollmentId, status, revision | یک job منطقی مطابق policy |
| `sites.page-published.v1` | Sites | Nuxt/Cache/Audit | siteId, pageId, revisionId | purge cache همان site |
| `identity.session-revoked.v1` | IAM | Gateway/Audit | identityId, sessionId, reasonCode | رد نشست بعدی |

## 6. ماتریس مجوز پایه

تصمیم نهایی همیشه در سرویس مالک منبع اجرا می‌شود:

`authenticated AND membership_active AND permission_match AND scope_allowed AND entitlement_active AND resource_policy_satisfied`

deny بر allow مقدم است. scope خالی به معنی کل سازمان نیست. منوی پنهان کنترل امنیتی محسوب نمی‌شود.

| بازیگر | Tenant/Org | Billing SaaS | Site/Page | School/Enrollment | Attendance | داده حساس |
|---|---|---|---|---|---|---|
| Platform Super Admin | metadata ضروری؛ دسترسی داده با grant موقت | مدیریت با دو تأیید برای refund | فقط پشتیبانی ممیزی‌شده | پیش‌فرض deny | پیش‌فرض deny | deny مگر approval و banner |
| Tenant Owner | واحدهای تابع مصوب | مشاهده/خرید/تمدید | مالک و تفویض محدود | مدیران را منصوب می‌کند | گزارش تجمیعی مجاز | field mask |
| Org Admin | scope خود و زیرشاخه‌های policy‌شده | مشاهده سهمیه | سایت‌های همان scope | مدیریت واحدهای مجاز | گزارش همان scope | deny مالی/سلامت خارج وظیفه |
| School Principal | یک/چند مدرسه انتسابی | فقط وضعیت entitlement | سایت مدرسه با permission | سال، کلاس، کاربران مدرسه | تأیید و گزارش مدرسه | mask مشاوره/حقوق |

| Guardian | فقط رابطه فعال | پرداخت بدهی/خدمت مجاز | public | فقط فرزند پیوندخورده | مشاهده فرزند | consent و field mask |
| Student | context شخصی | deny | public | فقط پرونده و محتوای منتشرشده | مشاهده شخصی | داده دیگران deny |
| Device/Service | credential و scope ثابت | deny | deny | mapping محدود | ingest فقط device خود | بدون biometric template |

## 7. قرارداد استقرار و Worker

- کانال نصب و انتشار، GitHub Actions با Runner/Worker محدود و ثبت‌شده است؛ ProjectMaker از SSH مستقیم برای استقرار استفاده نمی‌کند.
- مقصد برنامه‌ریزی‌شده `https://srun.ir/eduapp` با base path برابر `/eduapp` است.
- Nginx باید `/eduapp/api/` را به Gateway، `/eduapp/api/docs` و `/eduapp/api/openapi.json` را به مستندات Gateway، مسیرهای asset را به سرویس مجاز و سایر مسیرهای `/eduapp/` را به frontend مربوط route کند؛ تنظیم نهایی پس از inventory Worker و تست `nginx -t` فعال می‌شود.
- IP، پورت و credential سرور در secret store یا GitHub Environment نگهداری می‌شوند؛ secret یا private key وارد repo، log یا artifact نمی‌شود.
- Workflow فقط artifact امضاشده و pin‌شده به commit را نصب می‌کند؛ checkout دلخواه، `curl | bash` و اجرای ورودی کاربر به shell ممنوع است.
- Runner باید label اختصاصی، environment protection، concurrency lock، timeout و حداقل مجوز `contents: read` داشته باشد.
- production پس از build/test/security gates، backup، health check و approval محیط اجرا می‌شود؛ failure باید rollback یا توقف fail-closed داشته باشد.
- Nginx، TLS، DNS و مسیر واقعی deploy تا inventory فقط‌خواندنی Worker تأیید نشده‌اند و نباید موفق فرض شوند.
