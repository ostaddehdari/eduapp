# S05-W06 · واگذاری مدیریت سایت و مجموعه

نسخه `1.0.0`؛ `FR-007`؛ مالک درخواست‌های seat تفویضی `commercial_billing`. خرید seat به‌تنهایی هیچ عضویت IAM یا نقش مدیریتی نمی‌سازد.

| عملیات | شرط |
| --- | --- |
| `request` | درخواست‌کنندهٔ مجاز، اشتراک پرداخت‌شده و فعال، ظرفیت خالی seat، مالک فعلی معتبر، دامنهٔ سازمانی موجود، هویت delegate متفاوت از مالک، تاریخ انقضای حداکثر ۳۶۶ روز و کلید تکرار UUID. |
| `decide(approve)` | هویت مالک فعلی tenant و سیاست مستقل شامل MFA؛ تأیید فقط برای همان scope و delegate ثبت‌شده. |
| `canManage` | هر بار به صورت زنده tenant، delegate، scope دقیق، تأیید، انقضا، لغو و فعال بودن اشتراک را می‌سنجد. |
| `decide(revoke)` | مالک با MFA، لغو فوری؛ دادهٔ مشتری، مالک اصلی و اشتراک باقی می‌مانند. |

جدول `commercial_billing.management_delegations` در migration `0017-management-delegation.sql` با RLS اجباری و کلید تکرار در هر tenant ساخته می‌شود. runtime Billing فقط فیلدهای مشخص را درج می‌کند و فقط زمان تأیید/لغو را تغییر می‌دهد. `resolveOwner` و `scopeExists` باید از سرویس مالک tenant خوانده شوند؛ `authorizePurchase` و `authorizeOwner` باید از سیاست مستقل هویت و MFA بیایند. مصرف‌کنندهٔ مدیریت سایت/مجموعه باید `canManage` را برای **هر** کنش حساس در کنار مجوز پایهٔ IAM اعمال کند؛ اتصال این مصرف‌کننده و API عمومی در انتشار backend بررسی می‌شود. بدون این اتصال نباید دسترسی تفویضی را فعال اعلام کرد.
